# 每章提示词模板（可直接复制复用）

> **用法**：每章按 P1 → P2 → P3 → P4 → P5 顺序执行。
> 提示词里的 `{ }` 为占位符，执行前替换。
> **AI 合规边界（2026 治理口径）**：AI 可做外环（检索、校对、润色、起名）与中环（大纲骨架、场景初稿、对话初稿，须深度改写 ≥60%）；
> **内环严禁交给 AI**——核心人设、主线冲突、关键情节转折、情绪爆点、名场面、金句，必须你本人定。
> 模板中标注【人填】的字段，不要交给 AI 生成。

---

## P1 · 章前上下文装配（机器做，不占脑力）

```bash
python tools/ctx.py pack --chapter {章号} --out 04-context/pack-{章号}.md
```
输出即本章上下文包（A 常驻 + B 近期 + C 按需），超预算会自动给出压缩提示。
**规则：只把 pack 文件贴给 AI，不要把整个项目扔进去。**

## P2 · 事件卡 → 场景卡（可选，卡壳时用）

```
角色：你是网文结构工程师，只做结构，不做文字。
输入：
  【卷目标】{卷目标}
  【本章目标】{一句话可验证动作}【人填】
  【在场人物】{编号+姓名}
  【时间/地点】{D+XX / LXXX}
  【上一章结尾】{上一章最后 200 字}
任务：把本章拆成 2–4 个场景，每个场景输出六行：
  地点 / 时间 / 在场 / 场景目的 / 冲突（谁要什么谁挡着）/ 结果（局面变了什么）/ 信息增量
约束：
  ① 每个场景必须有"局面变化"，平的场次直接标【建议删除】
  ② 不能引入本章目标之外的新人物与新设定
  ③ 不得违反【人填】的本章目标
  ④ 输出不超过 400 字
```

## P3 · 正文写作（核心）

```
角色：你是番茄长篇连载的代笔助理，负责场景初稿。最终文字由我重写，你只需把骨架与对话写到 70 分。

【必读上下文】（即 pack 文件内容，逐字粘贴）
{粘贴 04-context/pack-{章号}.md}

【本章事件卡】
章号/章名：
本章目标：
在场人物：
时间/地点：
核心事件：
转折点：
爽点类型：
章末钩子类型 + 强度要求：★★★★
禁止事项（违反即作废）：
字数：2000–2600

【硬标准】
① 前 300 字内必须有新信息或新动作
② 每 300 字至少一次「新信息 / 新动作 / 新情绪」
③ 本章 ≥1 个爽点（开篇期 ≥2）
④ 章末钩子用指定类型，强度 ≥★★★
⑤ 对话单句 ≤30 字；无一段纯描写超过 200 字
⑥ 专有名词严格使用【名词规范表】，不得自造别名
⑦ 人物行为不得违反各自人物卡的「降智护栏三不做」
⑧ 不得让任何人知道他在逻辑上不该知道的信息
⑨ 不得出现世界观说明段落（设定只通过场景与对话揭示）
⑩ 涉及伤/毒/恢复的，遵守时间线台账的恢复期

【去 AI 味】
⑪ 情绪用动作与身体反应表达，不用"他感到愤怒/内心复杂"
⑫ 句式参差，避免排比与三段式
⑬ 允许 1–2 处口语、断句、答非所问
⑭ 禁止"仿佛整个世界都安静了""这一刻，他明白了"这类套话

输出：本章正文，只有正文，不要解释，不要备注。
```

## P4 · 章节摘要生成（完稿后立刻做，字段不可改）

```
角色：你是长篇一致性管理员。
输入：第 {章号} 章正文全文 + 上一章摘要 + 四大台账相关行。
任务：按下列 schema 输出本章摘要，字段顺序与字段名不得更改，总字数 ≤300 字。

章号: 
章名: 
字数: 
时间: {D+XX HH:MM 或起止}
地点: {编号}
出场人物: {逗号分隔的编号}
本章目标: 
核心事件: {3 句内}
转折: 
爽点: 
章末钩子: {内容 + 强度}
信息增量: {读者新知道了什么；无则写"无"}
人物状态变更: {格式：C003 立场:中立→敌对；C001 持有:+怀表；无变化写"无"}
伏笔: {格式：埋 F0xx / 强化 F0xx / 回收 F0xx；无则写"无"}
线程: {A线/B线/C线各一句，未涉及写"无"}

遗留问题:

约束：
① 只写"变了什么"，不复述剧情
② 状态变更必须带箭头（→），机器要 diff
③ 信息增量填"无"的，在最后另起一行标【注水风险】
④ 不得臆造正文里没有的信息
```

## P5 · 台账同步（摘要生成后执行）

```
角色：你是台账维护员，只做增量更新，不重写已有内容。
输入：第 {章号} 章摘要 + 当前的 09-伏笔台账.md / 10-时间线台账.md / 11-线程台账.md / 01-story-bible/characters/*.md

任务：输出一份「变更 diff」，格式为：
  【人物】文件名 | 字段 | 旧值 → 新值
  【伏笔】编号 | 埋/强化/回收 | 章号 | 状态变更
  【时间线】新增行（章号/时间/时长/地点/事件/人物）
  【线程】编号 | 占比变化 | 状态变化
  【名词】新增名词（如有）| 标准名 | 类型 | 释义
  【待恢复项】新增/完成（伤、毒、闭关）

约束：
① 只输出 diff，不要复述整张表
② 若摘要中出现台账里没有的新名词/新人物/新能力 → 单列【待登记】提醒我确认
③ 若发现与既有台账冲突（时间倒退、人物复活、伏笔重复编号）→ 单列【冲突】并说明冲突点
④ 不得修改 L0 层设定；需要改 L0 时，输出【L0 变更申请】并说明受影响章号
```

## P6 · 一致性终检（每章快速版 / 每 20 章完整版）

```
角色：你是长篇一致性审查员，只挑毛病，不夸奖。
输入：第 {章号} 章正文 + 本章摘要 + 近 3 章摘要 + 相关人物卡 + 时间线台账 + 伏笔台账。

按四类输出问题，每条给【位置（第几段/第几句）】【问题】【为什么是问题】【改法】：

A. 时间线冲突：倒退、行程不成立、恢复期不符、昼夜季节矛盾
B. 性格漂移：决策违背降智护栏、语言习惯不一致、动机断裂、信息污染（知道了不该知道的）
C. 能力膨胀：超出档位上限、越级无代价、临时新增能力、反派不够强
D. 伏笔/线程：该强化未强化、回收无回报、支线超限、线头过多

约束：
① 没有问题就写"无"，不要为了凑数硬找
② 每条必须给可执行改法，禁止"建议加强人物塑造"这种废话
③ 严重程度分级：🔴 必改（读者会发现） / 🟡 建议改 / ⚪ 可忽略
```

## 附：批量与复用技巧

| 场景 | 怎么做 |
|---|---|
| 一次写 5 章 | 每章独立跑 P3，**不要一次让 AI 写 5 章**——第 3 章起必崩 |
| 换 AI / 换会话 | 只需贴 `04-context/CURRENT.md` + `pack-N.md`，不需要历史对话 |
| 卡文 | 跑 P2 拿场景卡；仍卡 → 回卷纲层看「卷末必须发生」 |
| 想改设定 | 先改 `00-故事圣经.md` 并登记变更日志，再跑 P6 排查受影响章节 |
| 卷末 | 跑 P4 变体：把本卷全部摘要压成 ≤2000 字卷摘要，存 `04-context/archive/` |
