# 原创证据链

> **目的**：当有人问"这是你写的吗"，你能拿出时间线、过程稿和决策记录，而不是一句"是我写的"。
> 资源库口径参考：40 号《反洗稿自律公约与原创证据链管理》、41 号《AI 辅助创作合规边界》。
> 本文为创作管理方法论，**不构成法律意见**；涉实质性版权判断请咨询专业人士。

---

## 1. 三类证据（按证明力排序）

| 证据 | 怎么留 | 证明力 |
|---|---|---|
| **① 时间戳** | 文件创建/修改时间 + 本表的创作日志 | 中（可补强） |
| **② 过程稿** | 事件卡 → 场景卡 → 初稿 → 成稿，逐级保留 | **高**（最能证明"从无到有"） |
| **③ 决策记录** | 为什么这样写、排除了哪些方案 | 高（证明独立创作思路） |

**核心原则：保留"从无到有"的过程，比保留成品重要得多。**

## 2. 每章创作日志（写完一章立刻填一行）

| 章号 | 日期 | 事件卡完成 | 初稿完成 | 成稿完成 | 人工改写占比 | AI 使用范围（外/中/内环） | 借鉴来源（填编号，无则"无"） | 备注 |
|---|---|---|---|---|---|---|---|---|
| 001 |  |  |  |  | % | 外环：起名 / 中环：无 | 无 |  |
| 002 |  |  |  |  |  |  | R01（见台账#1） |  |

**AI 使用范围必须如实填**：
- 外环（完全可用）：资料搜集、校错别字、词句润色、起角色名、想书名备选
- 中环（须深度改写 ≥60%）：大纲框架、章节骨架、场景初稿、对话初稿
- 内环（**严禁 AI**）：核心人设、主线冲突、关键情节转折、情绪爆点、名场面、金句

## 3. 过程稿存放（推荐目录）

```
99-archive/versions/ch0001/
├── 01-事件卡.md
├── 02-场景卡.md
├── 03-初稿.md        （AI 初稿原始输出，不修改地保存）
├── 04-改写稿.md      （你的改写过程）
└── 05-成稿.md        （= 03-chapters/ch0001.md）
```

**注意**：`03-初稿.md` 要**原样保存、不做润色**——它就是"我做了深度改写"的证据。

---

## 4. 版本留痕建议

```bash
# 若用 git（推荐，天然时间戳 + diff）
git init && git add . && git commit -m "ch0001 初稿"
# 每章一提交，历史即证据
```

不用 git 也行，但必须保证：过程文件**只增不改**，成稿覆盖前先把旧版复制进 `99-archive/versions/`。

---

## 5. 每次发布前跑的三条检查

```bash
python tools/ref.py scan      # 表达污染：连续相同 ≥12 字即报警
python tools/ref.py report    # 借鉴度：单源占比 / 依赖度 / 改造度
python tools/ctx.py check     # 一致性：与借鉴无关，但顺手跑
```

把输出**截图或复制进本文件末尾的「检查留痕」**，形成时间点证据。
